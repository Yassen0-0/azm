Every assumption or judgment call made while building Azm, newest last. Format: date — decision — why.

## Phase 0 — tooling (2026-09-26)

- **2026-09-26 — Design inputs moved into `ROOT/inputs/`.** They were delivered loose in ROOT; the brief expects `inputs/`. `AZM_BOOTSTRAP_PROMPT.md` was later moved to `docs/ORIGINAL_BRIEF.md` (see the layout entry below).
- **2026-09-26 — `env.sh` also redirects `HOME` to `.tooling/home`** (plus `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME`). Flutter/Dart write settings and analytics state to `~`, the Kotlin daemon writes under `~/Library`, and git reads `~/.gitconfig`. Redirecting `HOME` is the only reliable way to keep all of that inside ROOT. The real home is exported as `AZM_REAL_HOME` and only `./ios_env` uses it (see below). Side effect: a git commit inside ROOT won't see the user's global git identity, which is fine because the brief requires a repo-local identity anyway.
- **2026-09-26 — `env.sh` resolves its own location with `BASH_SOURCE` / zsh `%x` and falls back to `$0`.** The brief suggests `$(cd "$(dirname "$0")" && pwd)`, but when a file is *sourced* from bash, `$0` is the shell's name, not the script's path. The intent (paths relative to the script) is unchanged.
- **2026-09-26 — Portable JDK: Eclipse Temurin 21.0.12.1+1 (LTS, aarch64) in `.tooling/jdk/`.** The Android cmdline-tools and Gradle need a JDK. A JDK already exists at `~/dev/jdk-17`, but it is outside ROOT, so it is not used. `.tooling/jdk/current` is a relative symlink, which keeps it portable. `flutter config --jdk-dir` points to it, and so does `JAVA_HOME`.
- **2026-09-26 — `JAVA_TOOL_OPTIONS=-Duser.home=… -Djava.io.tmpdir=…`.** JVMs on macOS take `user.home` from the passwd entry and ignore `$HOME`, so without this setting Gradle, the Kotlin daemon and sdkmanager would write to the real home. The cost is a harmless `Picked up JAVA_TOOL_OPTIONS` line on stderr.
- **2026-09-26 — Flutter pinned to 3.47.5.** It is the `stable` branch HEAD, commit `6a19cca564`. The SDK was cloned with `-b stable` rather than checked out as a detached tag so `flutter doctor` reports channel `stable`. The pin is enforced by the commit hash recorded in the README.
- **2026-09-26 — Portable Ruby 3.4.5 (Homebrew's standalone `portable-ruby` tarball) in `.tooling/ruby/`, instead of system Ruby.** System Ruby is 2.6.10, and CocoaPods' current dependencies (`ffi`, `drb`, …) need Ruby ≥ 2.7/3.0, which RubyGems 3.0 cannot resolve around. The tarball is a plain download, and nothing is installed through Homebrew. Gem binstubs in `.tooling/gems/bin` are `/bin/sh` launchers that run the `ruby` found on `PATH`, so they still work after a move. Their embedded `#!…/ruby` line is absolute, though, and `tools/relocate.sh` rewrites it.
- **2026-09-26 — CocoaPods is installed only as a fallback.** Flutter 3.47 enables Swift Package Manager by default on stable. CocoaPods (1.17.0) is only used for plugins that don't ship SPM support yet.
- **2026-09-26 — Android packages:** `platforms;android-36` is Flutter 3.47's default `compileSdk`/`targetSdk`, preinstalled so Gradle doesn't need to download it. `platforms;android-37.2` is the latest stable platform. Also installed: `build-tools;37.0.0`, `ndk;28.2.13676358` (Flutter's default `ndkVersion`), `platform-tools`, `emulator`, and `system-images;android-37.0;google_apis_playstore;arm64-v8a` for the emulator. That image is the newest one with a standard 4 KB page size; the 37.1/37.2 images are 16 KB-page only.
- **2026-09-26 — `sdkmanager` is deprecated in cmdline-tools 23 in favour of `android sdk`.** It still works and is what Flutter's tooling expects, so it was used.
- **2026-09-26 — `env.sh` replaces `PATH` with sandbox tools plus macOS system dirs only, and unsets inherited toolchain variables.** The user's shell profile exports `JAVA_HOME`, `ANDROID_HOME`, `GRADLE_USER_HOME` and `PUB_CACHE`, all pointing at `~/dev`, and its `PATH` contains a second Flutter SDK, JDK and Android SDK there. `flutter doctor` flagged a conflicting second `adb`. The original values stay available in `AZM_REAL_PATH`/`AZM_REAL_HOME` for reference, and nothing uses them.
- **2026-09-26 — `AZM_ROOT` is resolved with `pwd -P`.** The volume is case-insensitive, and when a shell was opened as `.../desktop/azm`, Flutter warned that its SDK path and `PATH` differed in case. `pwd -P` returns the canonical on-disk casing.
- **2026-09-26 — Flutter web and desktop targets disabled** (`flutter config --no-enable-web --no-enable-*-desktop`). Azm targets Android and iOS only, so this removes the irrelevant Chrome check from `flutter doctor`.
- **2026-09-26 — AVD `azm_api37`** (Pixel 8 profile, API 37 Google Play image) created in `.tooling/android-user/avd`. A headless boot was verified (`sys.boot_completed=1`, SDK 37 / Android 17). The emulator's console token and `.android` state landed in `.tooling/home`, which confirms the `HOME` redirect works.
- **2026-09-26 — Path-bound items found in `.tooling`:** absolute paths in `.tooling/android-user/avd/*.ini` and `azm_api37.avd/*.ini`/`*.txt`, absolute `#!` lines in `.tooling/gems/bin/*`, Flutter's `jdk-dir` setting in `.tooling/home/.config/settings`, and absolute pub-cache paths in `.tooling/flutter/packages/flutter_tools/.dart_tool/package_config.json`. `tools/relocate.sh` handles all of them.

- **2026-09-26 — The git repo lives at ROOT.** `.gitignore` excludes `.tooling/`, `inputs/`, `media/`, `data/catalog/*.sqlite` and secrets: `.env*`, keystores, `key.properties`, `*.p8`/`*.p12`/`*.mobileprovision`, `GoogleService-Info.plist`, `google-services.json`, `firebase_options.dart` and R2 credential files. Flutter's default ignores are written with `**/` so they apply under `app/`. `git init` and the first commit are still Phase 1, step 5.
- **2026-09-26 — `./ios_env` wrapper for Apple code signing.** It sources `env.sh` and then sets only `HOME` back to the real home, so the login keychain, Xcode accounts and provisioning profiles are visible. PATH, pub-cache, gems/CocoaPods, Gradle, `XDG_*` (Flutter settings) and `TMPDIR` stay in ROOT. When the command is `xcodebuild` and has no `-derivedDataPath`, the wrapper adds `-derivedDataPath .tooling/xcode-derived`. Use it for `flutter run` on a physical iPhone, `flutter build ios`/`ipa`, and signed `xcodebuild`. It is not needed for Android or the Simulator. Accepted spill into the real `~/Library` in this mode, because Xcode is the allowed exception: DerivedData/ModuleCache from `flutter build ios` (Flutter does not pass `-derivedDataPath`) and Xcode's own signing/SwiftPM caches. A wrapper was chosen over a flag in `env.sh` so the real `HOME` can never leak into a shell by accident; it applies to one command only.
- **2026-09-26 — `AZM_REAL_HOME` is derived from the user database (`~$(id -un)`), not from `$HOME`.** Sourcing `env.sh` twice would otherwise record the already-redirected `.tooling/home` as the "real" home.
- **2026-09-26 — `CP_CACHE_DIR=.tooling/cocoapods/cache`.** CocoaPods otherwise caches under `~/Library/Caches/CocoaPods`, which would be the real home under `./ios_env`.
- **2026-09-26 — `tools/relocate.sh` written early** (the brief schedules it for Phase 1). It derives ROOT from its own location and rejects paths with spaces or non-ASCII characters. It finds the old ROOT inside each AVD `.ini` and rewrites it case-insensitively, because APFS is case-insensitive and one file had stored `Desktop` while another had `desktop`. It uses the system `/usr/bin/perl` for in-place edits, a system binary like `git`/`curl`. It was tested on an APFS copy-on-write clone of ROOT inside `.tooling/tmp`, moved and then renamed: `flutter doctor` passed, the AVD booted from the new path, and no stale paths remained. The clone was then deleted.

## Phase 3 — data layer (2026-09-26)

- **2026-09-26 — CORRECTION: the Lifted comparison picks the SMALLEST qualifying object, not the largest.** The Phase 1 entry said "largest", but the brief's own example (8,450 kg → 6 cars) needs smallest-first (the largest-first rule would give 1 elephant). SPEC.md and `liftedComparison()` now go car → pyramid block → elephant.
- **2026-09-26 — Arabic names: the "50 most common" list** was picked by hand from gym staples across chest (11), back (11), legs (10), shoulders (6), arms (10) and abs (2). The names use Egyptian gym usage (e.g. `منشار` for the one-arm dumbbell row, `رجل أمامي`/`رجل خلفي` for leg extension/curl, `تراي فرنساوي`, `فراشة`). All are `reviewed: false`. `0292` (one-arm bent-over row) was chosen over `0293` (two-dumbbell row) because "منشار" means the one-arm version. Aliases include English-in-Arabic-letters (`بنش برس`, `لانجز`) and one Latin alias (`RDL`). No aliases were added just for ة/ه or أ/ا spellings, because normalization already covers them.
- **2026-09-26 — Program format:** `reps` is `[min, max]`, and `level` (beginner/intermediate) was added. The three programs use only exercises that have Arabic names (29 distinct). When copied into routines, `target_reps` = the range max (recorded in DATA.md for the routines feature).
- **2026-09-26 — Catalog programs live in the catalog DB** (`catalog_programs`: id, sort, JSON `data`), not as a separate asset, so they are replaced atomically with the exercises on a version bump.
- **2026-09-26 — Catalog versioning:** `data/catalog/catalog_version.json` = `{version, input_sha256}`. The hash covers the three input files plus `builderRevision` in the script, and the version bumps only when the hash changes. The app compares a tiny bundled `catalog_version.txt` first, so the 900 KB asset DB is only copied and read on the first launch or after an update.
- **2026-09-26 — The bundled catalog (`app/assets/catalog/*`) is committed**, even though `data/catalog/catalog.sqlite` stays gitignored as the brief asks. Without it a fresh clone could not build until someone ran the tool. It is small (904 KB) and fully reproducible with `tools/build_catalog.sh`.
- **2026-09-26 — Installer reads the asset DB with `package:sqlite3` and bulk-inserts through Drift** in one transaction, rather than `ATTACH` (SQLite refuses ATTACH inside a transaction, and this keeps the logic testable with in-memory data). It installs only when the bundled version is **newer** (or none is installed), so downgrading the app keeps the newer catalog.
- **2026-09-26 — `tools/` is its own pure-Dart package** (`azm_tools`: `sqlite3`, `crypto`, `lints`). It imports `app/lib/core/utils/arabic_normalize.dart` by relative path, which is why that file must stay import-free. The `avoid_relative_lib_imports` lint is suppressed on that one line.
- **2026-09-26 — Display names:** the dataset is lowercase, so `name_en` is Title Case with acronyms kept (EZ, POV, RDL, V.). Four names containing the `в°` encoding glitch are fixed to `°` at build time, and the raw data is untouched.
- **2026-09-26 — Normalizer extras beyond the brief:** it also maps `ٱ` (alef wasla) → `ا`, removes invisible marks (ZWSP/ZWNJ/ZWJ/LRM/RLM/BOM) instead of treating them as spaces, and treats NBSP/Unicode spaces as whitespace.
- **2026-09-26 — Drift details:**
  - `SetType` is defined once in `core/utils/workout_math.dart` and stored via `textEnum`.
  - The `clientDefault` helpers (`newUuid`, `utcNow`) must be public, because Drift copies them into the generated part file.
  - `PRAGMA foreign_keys = ON` is set in `beforeOpen`.
  - Extra index `workout_exercises(exercise_id)` for per-exercise history.
  - Generated `app_database.g.dart` is committed.
- **2026-09-26 — PR detection:** per workout and per PR type, only the single best eligible set (first on ties) can be the PR, and it must strictly beat all earlier workouts' best. `PrBests.fromSets` ignores warm-ups.
- **2026-09-26 — Settings persistence implemented** (Phase 2 TODO). `locale`/`theme` are written to the `settings` table on every change and loaded in `main()` before the first frame. Tests use an in-memory store.
- **2026-09-26 — Startup order:** open DB → install catalog if needed → load settings → `runApp`. On the first launch this runs behind the native splash. The measured on-device result: catalog v1 installed, 1,324 exercises, 50 Arabic, 3 programs, and the partial unique index present.
- **2026-09-26 — MediaResolver config via `--dart-define`:**
  - `AZM_MEDIA_BASE_URL` sets the media server. With no URL (the default), every exercise shows the fallback icon.
  - A licence allow-list, `MediaConfig.licensedExerciseIds`, is empty until media is bought. It is owner-maintained, and any id not in it resolves to null.
  - `AZM_MEDIA_ALLOW_ALL=true` bypasses the allow-list for dev only, and is ignored in release builds (`dart.vm.product`).

  - Android **debug** manifest: `usesCleartextTraffic="true"`; release builds stay HTTPS-only.
  - iOS: `NSAppTransportSecurity/NSAllowsLocalNetworking` (local-network hosts only).
  - The main Android manifest gains `INTERNET` for production media from R2; Flutter's template only had it in debug.
