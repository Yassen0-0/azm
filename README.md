# Azm (عزم)

Hevy-style gym tracker for Android and iOS. Flutter, Arabic-first, fully bilingual.

This folder (the **ROOT**) is fully self-contained: code, data, design system, docs **and** every SDK and cache live inside it. It can be moved to another disk (see [Moving the folder](#moving-the-folder)).

> **Status: v1 is feature-complete** (tag `v1.0.0-rc1`, 2026-09-27): workout logging + rest timer, routines + ready programs + onboarding, exercise library/picker/detail (1,324 exercises, all with Egyptian-gym Arabic names), history + stats + PRs, settings + backup/restore + licences, brand icons/splash. Verified on the Android emulator and the iOS Simulator in Arabic and English. **What's left is owner work**, listed below and in [docs/PLAN.md](docs/PLAN.md) → *v1 status*.

### Remaining owner tasks (not agent work)

1. **Gym visual media licence**: buy the licence for the ~150–200 exercises to show, record it in `docs/LICENSES.md`. Until then every exercise shows the fallback icon (the release behaviour).
2. **Cloudflare R2 + upload script**: create the bucket + custom domain; then `tools/upload_media_r2.dart` (PLAN §8, blocked on 1) uploads only licensed ids and prints the base URL for `AZM_MEDIA_BASE_URL`.
3. **Firebase project + Crashlytics**: create the project, drop `google-services.json` / `GoogleService-Info.plist` (gitignored); then PLAN §9 wires `firebase_crashlytics`.
4. **Apple Developer account + TestFlight** (and Google Play console): signing keys kept out of git; `./ios_env flutter build ipa` for TestFlight.
5. **Real-device checklist**: [docs/DEVICE_TEST_CHECKLIST.md](docs/DEVICE_TEST_CHECKLIST.md) (haptics, notifications, share sheet/file picker, launcher icons, performance …).
6. **Arabic names review**: 1,274 names ship with `reviewed: false` (`data/ar/exercise_names_ar.json`; review tables `docs/review/names_batch_01…13.md`, 109 flagged ⚠️; identical pairs in `docs/review/duplicates.md`). Flip `reviewed` to `true` as you confirm them, then `tools/build_catalog.sh`.

## The sandbox rule

Nothing is read, written, installed or downloaded outside ROOT. The only exceptions are Xcode itself, the system `git`, `curl` and `perl` in `/usr/bin`, and **credentials in the macOS Keychain** (the GitHub login token). Both Xcode signing and the Keychain need the real HOME, so they run through a wrapper: `./ios_env` for Xcode, `./gh_env` for GitHub (see below).

Always run commands from ROOT like this:

```sh
source ./env.sh && flutter doctor
```

**Guard rails:** `env.sh` fails when `flutter` isn't the `.tooling` one (so `source ./env.sh && <cmd>` stops), and a Claude Code PreToolUse hook (`.claude/settings.json` → `tools/hooks/require_env_sh.sh`) blocks any agent Bash command on the Mac that runs `flutter`/`dart` without `source ./env.sh` (or `./ios_env` / `./gh_env`) in the same command. The hook does nothing on Linux.

`env.sh` (paths are relative to its own location):

| Variable | Points to |
|---|---|
| `PATH` | sandbox tools + `/usr/bin:/bin:/usr/sbin:/sbin` only — your shell's PATH is **dropped** |
| `HOME` | `.tooling/home` (catches everything tools write to `~`) |
| `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME` | `.tooling/home/...` (Flutter settings live here) |
| `TMPDIR` | `.tooling/tmp` |
| `FLUTTER_ROOT`, `PUB_CACHE` | `.tooling/flutter`, `.tooling/pub-cache` |
| `JAVA_HOME` | `.tooling/jdk/current` (+ `JAVA_TOOL_OPTIONS` forcing `user.home`/tmpdir into ROOT) |
| `GRADLE_USER_HOME` | `.tooling/gradle` |
| `ANDROID_HOME`, `ANDROID_SDK_ROOT` | `.tooling/android-sdk` |
| `ANDROID_USER_HOME`, `ANDROID_EMULATOR_HOME`, `ANDROID_AVD_HOME` | `.tooling/android-user` (`/avd`) |
| `GEM_HOME`, `GEM_PATH` | `.tooling/gems` (CocoaPods) |
| `CP_HOME_DIR`, `CP_REPOS_DIR`, `CP_CACHE_DIR` | `.tooling/cocoapods/...` |
| `AZM_XCODE_DERIVED` | `.tooling/xcode-derived` — always pass `-derivedDataPath "$AZM_XCODE_DERIVED"` to `xcodebuild` |

Java prints a harmless `Picked up JAVA_TOOL_OPTIONS: ...` line on every run. That line is how Java gets pointed inside ROOT.

### Note: `~/dev` holds a separate, older toolchain, and it is deliberately ignored

This Mac already has a Flutter SDK, pub-cache, JDK 17, Android SDK and Gradle home under `~/dev`. The shell profile exports `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, `GRADLE_USER_HOME` and `PUB_CACHE` pointing there, and puts them on `PATH`. **`env.sh` unsets all of those and rebuilds `PATH` from scratch**, so Azm never uses or modifies `~/dev`. Don't "fix" this by adding `~/dev` back. If `flutter doctor` ever mentions a path outside ROOT, `env.sh` was not sourced.

## iOS signing: `./ios_env`

The redirected `HOME` hides your login keychain, Xcode accounts and provisioning profiles. That makes **code signing** (physical device, release/archive builds) fail. For those commands, use the wrapper. It loads `env.sh` and then restores only your real `HOME`:

```sh
./ios_env flutter run -d <iphone-id>        # physical iPhone
./ios_env flutter build ios --release
./ios_env flutter build ipa
./ios_env xcodebuild -workspace app/ios/Runner.xcworkspace -scheme Runner ...   # -derivedDataPath added automatically
```

Everything else (PATH, pub-cache, gems, CocoaPods, Gradle, Flutter settings, TMPDIR) stays inside ROOT. **Not needed** for Android or the iOS Simulator, which use plain `source ./env.sh && ...`.

**Xcode's build cache always goes to the real home.** Every `flutter build ios` / `flutter run` on iOS, **including Simulator builds with plain `env.sh`**, writes Xcode's intermediates to your real `~/Library/Developer/Xcode/DerivedData/Runner-<hash>`: Xcode ignores the redirected `HOME` and Flutter does not pass `-derivedDataPath`. Redirecting it would need a global Xcode preference, which the sandbox rule forbids, so it is accepted as part of the Xcode exception. Simulators and their app data also live in Xcode's `~/Library/Developer/CoreSimulator`. Delete the `Runner-*` folder any time; Xcode rebuilds it.

## GitHub: `./gh_env`

The GitHub CLI lives in `.tooling/gh` (on `env.sh`'s PATH). Its login token is stored in the **macOS Keychain**, which is only reachable with the real HOME, so every command that talks to GitHub goes through the wrapper:

```sh
./gh_env gh auth login --hostname github.com --git-protocol https --web   # once, in the browser
./gh_env gh auth status
./gh_env git push origin main
```

`gh_env` sources `env.sh`, then restores only `HOME`. gh's non-secret config stays in `.tooling/home/.config/gh` (`GH_CONFIG_DIR`) and git's "global" config in `.tooling/home/.gitconfig` (`GIT_CONFIG_GLOBAL`, so your real `~/.gitconfig` is never read). This repo's local git config uses `gh auth git-credential` for github.com. Tokens are never written to files.

## Tester APK releases (owner only)

Private GitHub prereleases on `Yassen0-0/azm`, one universal APK each: `v<version>-b<build>` with `azm-<version>-<build>.apk` attached.

```sh
# once per release: write docs/release_notes/v1.0.0-rc1-b<build>.md (Arabic + English), commit, push
source ./env.sh && tools/release_apk.sh --build-only   # build + verify only (dist/, gitignored)
source ./env.sh && tools/release_apk.sh                # build + verify + tag + prerelease + bump
```

- **Version:** `app/pubspec.yaml` `version: 1.0.0-rc1+<build>` is the single source; `<build>` is the next tester build. The script releases it, tags that commit, then bumps it and commits.
- **Checks before publishing:** signed with the upload key (certificate SHA-256), versionCode/versionName match pubspec, the asset list is printed and contains nothing from `media/` (path, GIF/video type, or SHA-256 match against every file in `media/`). The repo must be private.
- **Install on a phone:** download the APK from the release page (logged in to GitHub), allow "Install unknown apps" for the browser/Files app, open it. Later builds install over it as updates.

### Upload key: DON'T LOSE IT

`.tooling/secrets/azm-upload.jks` (gitignored, never pushed) signs every tester build; its password is only in the **macOS Keychain** (service `azm.android.upload`), read with the real HOME like `./gh_env`. **Losing the keystore or its password means installed copies can never be updated**: Android refuses an update signed with a different key, so every tester would have to uninstall (losing their data unless they exported a backup) and reinstall. (For Google Play later, this becomes the *upload* key of Play App Signing, which can be reset through Google; sideloaded tester installs can't.)

```sh
source ./env.sh && tools/upload_key.sh info     # fingerprints only
tools/upload_key.sh backup                      # YOU run it in Terminal; you type the zip password
```
`backup` writes `.tooling/secrets/azm-upload-key-backup-YYYYMMDD.zip` (keystore + its password, zip-encrypted with the password you type). **Copy it to Google Drive and to the SSD**, and keep the zip password somewhere else (a password manager). Restore: unzip, put the `.jks` back in `.tooling/secrets/`, and add the password to the Keychain with the command in the zip's README.

## Set up on a fresh Mac

Prerequisites: Xcode from the App Store (open it once so it installs its components), and ~15 GB free space. The ROOT path must not contain spaces or non-ASCII characters.

If you copy the whole ROOT, including `.tooling/`, you only need to run `tools/relocate.sh`. To rebuild `.tooling/` from nothing:

```sh
cd /path/to/azm
source ./env.sh
mkdir -p .tooling/{pub-cache,gradle,gems,cocoapods,android-sdk,android-user/avd,tmp,home,jdk,xcode-derived}

# Flutter
git clone -b stable https://github.com/flutter/flutter.git .tooling/flutter
git -C .tooling/flutter checkout 6a19cca56475dbfba1478ee68d7bd0c2ef891da1   # pin
flutter --disable-analytics && dart --disable-analytics

# JDK 21 (Temurin, macOS aarch64) -> .tooling/jdk, then:  ln -sfn jdk-21.0.12.1+1 .tooling/jdk/current
# Portable Ruby 3.4.5: github.com/Homebrew/homebrew-portable-ruby releases -> .tooling/ruby
source ./env.sh   # re-source so JAVA_HOME / ruby are picked up
flutter config --jdk-dir "$JAVA_HOME" --no-analytics --no-cli-animations \
  --no-enable-web --no-enable-macos-desktop --no-enable-linux-desktop --no-enable-windows-desktop

# Android SDK: unzip commandlinetools-mac_arm64-*_latest.zip to .tooling/android-sdk/cmdline-tools/latest
yes | sdkmanager --licenses
sdkmanager --install "platform-tools" "emulator" "platforms;android-36" "platforms;android-37.2" \
  "build-tools;37.0.0" "ndk;28.2.13676358" "system-images;android-37.0;google_apis_playstore;arm64-v8a"
echo no | avdmanager create avd -n azm_api37 -k "system-images;android-37.0;google_apis_playstore;arm64-v8a" -d pixel_8

# CocoaPods
gem install --no-document cocoapods

flutter doctor -v   # every path must be inside ROOT (except Xcode)
```

Start the emulator: `source ./env.sh && emulator -avd azm_api37 &`

## Moving the folder

```sh
ditto OLD_ROOT NEW_ROOT          # preserves symlinks + permissions
NEW_ROOT/tools/relocate.sh       # run from anywhere
```

`relocate.sh` also works after a plain rename, and it is safe to re-run. It:
1. deletes path-bound caches (`app/.dart_tool`, `app/build`, `app/ios/Pods`, generated Xcode/Gradle config, `.tooling/xcode-derived`, Xcode DerivedData in `.tooling/home`, Gradle daemons, `.tooling/tmp`);
2. rewrites absolute paths in the AVD `.ini` files (`.tooling/android-user/avd`);
3. rewrites the absolute `#!` Ruby path in the CocoaPods/RubyGems launchers (`.tooling/gems/bin`);
4. re-saves Flutter's `jdk-dir` setting and forces the Flutter tool to rebuild its dependency map;
5. runs `flutter pub get` + `pod install` (when `app/` exists);
6. runs `flutter doctor -v` and fails if `flutter` resolves outside ROOT.

It was tested on 2026-09-26 with a copy-on-write clone moved and then renamed inside `.tooling/tmp`: `flutter doctor` passed, the emulator booted from the new location, and no stale paths were left.
